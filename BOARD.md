1. ~~**Undeclared network call.**~~ **RESOLVED, committed 2026-08-19.** `google_fonts` no longer
   reaches `fonts.gstatic.com`: Inter and Sora ship as static weights under `assets/google_fonts/`
   and `main.dart` sets `GoogleFonts.config.allowRuntimeFetching = false`. The README's
   "offline-first / nothing is uploaded" and the Data Safety answers in `docs/PLAY_SUBMISSION.md`
   — which name `api.postcodes.io` (I-49) as the app's *only* runtime network call — are now
   accurate as written; **no doc edit was needed, the code caught up with the docs.** What replaces
   it: a `GoogleFonts` family or weight whose `.ttf` is not in that folder falls back to the
   platform font **silently**. Ship the file before you write the call. Still not registered in
   `docs/STOPSNOOZER_ISSUES.md` — see the log entry below.

   30,143,077 bytes and tracked. The repo is already 126 MB of loose objects. Every rebuild adds
   another 30 MB blob to history permanently. Consider Git LFS or a release artefact before the
   repo becomes painful to clone.

   least-verified code in the project. There is no native test harness at all.

  OFFLINE-FIRST CLAIM IS NOW TRUE. google_fonts no longer touches the network.
  analyze: No issues found · flutter test 32/32 · pytest tools/ 51/51.

  RCA
    Symptom:         an app whose whole premise is working underground, with no
                     signal, downloaded its fonts from fonts.gstatic.com on first
                     launch. The Play Data Safety answers declare only
                     api.postcodes.io, so this was also an undeclared network call.
    Root cause:      41 files call GoogleFonts.inter / GoogleFonts.sora. NOTHING was
                     bundled (no `fonts:` section), and allowRuntimeFetching was never
                     set, so it defaults to true. The package fetched and cached to
                     device storage on first use.
    Why it survived: every dev and test run happened on a connected machine, where the
                     fetch succeeds silently and instantly. The failure only shows on a
                     first launch with no connectivity — i.e. the actual use case.
                     No test can catch it; the suite has no network isolation.
    Edge cases:      first run in a tunnel = fallback to platform font, so the UI is
                     visibly wrong exactly when the app matters most.
    Fix:             Inter + Sora bundled at assets/google_fonts/ (12 static weights,
                     w400-w900, matching the six FontWeight values the code uses),
                     plus GoogleFonts.config.allowRuntimeFetching = false in main().
                     BOTH halves are required — assets alone still let it reach the
                     network first; the flag alone silently falls back to the system font.
    Guard:           none automated. Verify by first-launching a fresh install in
                     aeroplane mode and confirming headings still render in Sora.

  How the fonts were produced — this is not obvious and will be needed again:
    Google no longer publishes static weights for either family; ofl/inter and ofl/sora
    contain ONLY variable fonts. The 12 files were generated locally with
    fontTools.varLib.instancer from the upstream variable TTFs. Sora needed
    updateFontNames=False (its STAT table has no axis value at wght 500);
    google_fonts matches on FILENAME, so internal names do not matter.
    OFL-Inter.txt and OFL-Sora.txt ship alongside — the SIL Open Font License
    requires the licence to travel with the fonts.
  Cost: +2.4 MB of assets. Deliberate: correctness for an offline app beats APK size.

    omitted fonts.gstatic.com. No longer a submission blocker on that point.

      which needs a person.

  WHAT IT ACTUALLY FIXES. An app whose entire premise is working in a tunnel was downloading its
  fonts from fonts.gstatic.com on first launch. Offline first run = platform font, i.e. the UI is
  visibly wrong exactly when the app matters most. It was also an undeclared network call: the Data
  Safety answers in docs/PLAY_SUBMISSION.md state that api.postcodes.io is the app's ONLY runtime
  network call. That sentence was false and is now true. **No doc edit was needed — the code caught
  up with the docs.** Cost: +2.4 MB of assets, taken deliberately.

  `pubspec.yaml.bak-20260824` — **DELETED, not gitignored.** It was byte-identical to
  `git show HEAD:pubspec.yaml`, so git already held it; a permanent ignore rule for a one-off
  leftover would also hide the next accidental backup. `.gitignore` here ignores classes of
  regenerable, large or secret files, and a stray editor backup is none of those.
